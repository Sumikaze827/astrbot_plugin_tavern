# NPC 意图与原作参考（第一版）

## 职责与实际边界

本功能按世界开启 `rules.npc_direction.enabled`。不是每个 NPC 的常驻 agent。
身份、性格、能力与重要关系由作者维护；模型更新现有 NPC 时不能覆盖这些核心字段。
管理员编辑仍可校正设定。旧的 `duplicate_proposals` 不再进入 NPC 叙事输入。
现有 NPC 记忆保留最近 60 条，而不是永久保留最早 60 条。

人物名单分为上下文相关者、发言感知候选、独立决策对象。名字被提及不授予互动资格。
第一版确定性门控覆盖显式的本地发言、同场公开发言、已配置近距区域的私语、明确声学通路的喊话。
地点使用作者确认的精确映射、结构化空间凭证，或双方当前位置文字明显指同一处
（归一化后相等或互相包含）。
未知地点、泛称“王城”、旧叙事提及、模型高置信度都不是授权依据。

复合移动后发言、含糊指代、战斗观察、复杂偷听和远程传讯尚未接入通用结构化交付协议。
这些情形不触发未经授权的独立 NPC 决策，继续由既有裁定流程处理；不声称对全部自由文本完成了信息隔离。
不能把“未取得感知资格”描述成 NPC 已经拒绝或同意。

## 空间配置

`rules.npc_direction.interaction` 包含：

- `evidence_ids`：作者审查凭证列表，不能由模型写入。
- `scenes`：场景 ID 对象，`public_hearing` 明确允许公开发言；`whisper_same_zone` 仅在确认近距可闻时开启。
- `location_map`：完整位置文字到 `scene_id / zone_id / evidence_id` 的精确映射，禁止前缀匹配。
- `relations`：可选定向声学边，字段 `from / to / shout_content / evidence_id`。没有配置不跨场景传播。

运行状态可携带 `spatial`，必须含 `status=confirmed`、`location_text` 与登记的证据 ID。
位置文字变化而凭证未变，视为 stale，不拿旧凭证继续授权。
第一版未知地点需作者补充映射；没有自动把模型建议提升为权威空间事实。
传讯送达机制后续接入时，应复用同样的感知凭证，而不是把双方判为同场。

## 原作检索

可信本地配置：插件数据目录 `npc_source_registry.json`，以世界 slug 为键。
每个世界指定 `root` 与 `chapters`。每章显式列出批准的 `spans`：
`file/start/end/purpose/timeline`，purpose 为 motivation、scene 或 transition；
timeline 必须是作者筛选过的 `single_line_reference`。
只允许根目录下 Markdown，拒绝越界路径；限制文件大小、片段数和输入字数。
按当前章筛选，再按本轮文字相关性排序；每次最多两段，文件按修改时间缓存。

原文只给叙事参考，不直接传入 NPC 决策、不写入人物知识。
NPC 决策只获得该角色自己的核心卡、当前状态、最近知识及合法发言候选；
`actor_guidance` 是作者预先筛掉未来秘密的性格说明，不是原作事件结果。
无配置、文件不可读、没有批准片段时，明确降级，不能编造引用。

## 调用与提交

启用且存在 NPC 时，行动先作一次结构化语义分类（最多 650 输出 token、12 秒）。
只读身份、本轮输入及该玩家上轮已结算叙事，不读 NPC 私有知识；支持接话和代词。
线上不再依赖重要决定关键词或正则解析；失败保留未知，不回退到关键词猜测。
分类不授予感知或送达资格；代码仍过滤未知 ID、非原文发言、未结算移动和远程传讯。
有感知资格的交互对象才生成独立意图，最多两名，各一次、18 秒，输入隔离；普通对话也适用。
纯个人行动仍需分类，但没有独立 NPC 决策调用。
意图包含 stance、goal、intent、condition、reason，可另带 expression（态度/表达方式，不是台词）。
人物核心配置可加 voice_profile（称呼、句式、亲疏差异）；缺省依据原有性格与关系。不能直接写状态或结果。

最终叙事结合已锁定骰果生成。有相关人物卡或意图即检查成稿，不依赖意图非空；
检查指令腔、人物错位及口吻同质化；正式信件、必要限制和合理冷淡不自动判错。
首次检查超时/无效降级并记录 review_status，不冒充通过；已有拒绝后的复核失败仍不放行。
拒绝后走既有修正流程，修正稿再核验一次。仍不通过则不提交矛盾回合，保留已有骰果凭证；
不凭空生成“成功”的保底结果。此检查不能数学保证全部自然语言都无 OOC。

明确发言的知识更新由事务内感知记录产生，只记录“听到玩家如此陈述”，不证明陈述为真。
凭证包含源事件、回合、稳定行动 ID；同一次提交不重复添加。
非发言行动的知识结算仍沿用原流程，是第一版已知边界。
提交前核对 NPC 核心与运行状态 revision，结合原有会话 revision 和幂等回执防止过期决定落库。
日志 `meta.npc_direction` 保存触发、名单、引用位置及检查状态，不保存人物秘密或完整原文。

### 越界知识的处理（2026-09-20 修订）

过去 `validate_npc_ops` 发现模型给无感知依据的 NPC 写 `known_facts`（或自行写入
`spatial` 等凭证）时直接抛错，两次修正都不通过就作废整轮，玩家只看到
「本轮裁定未完成，世界状态没有改变」。线上复现：玩家走进作者 `location_map`
未登记的场景后，任何 NPC 都无法被认证为在场，而模型给同处一室的 NPC 记账是
自然行为——于是这一轮永远提交不了。

现在改为就地剥离：知识条目与凭证字段被丢弃，其余裁定与正文照常提交，违规记录进
`scope.sanitized_ops` 并写 warning 日志。这不降低安全性——被闸门开启的会话里，
`known_facts` 本来就只由感知回执写入，模型写的条目在提交路径上同样会被丢弃。

提示词新增 `<npc_knowledge_gate>`：点名本轮有感知依据的 NPC，或说明本轮无法认证
感知范围。无法认证时禁止写 `known_facts`，但允许正文照玩家行动与现场人物正常回应
书写——空名单只代表「范围未知」，不代表「现场没有人」。

## 回归与部署

### 持续同行小队

自由演绎例外：空间、联络、会合与行动可行性在前置 acceptance（full/partial/reduced）统一判断。
具有编译器生成的 freeform_acceptance 指令时，不再调用后置行动/对白检查否决整轮；
无法成立的求助等应在接收说明和正文中交代尝试范围、未实现效果与原因。
未确认的 join 和越界移动记录保留原小队、剥离无依据写入并记录 travel_adjustment，不用结构错误让玩家重试。
JSON 类型、真实骰果、事务一致性等结构与状态保障仍保留；非自由演绎路径不变。

`world_state.travel_groups` 保存稳定 participant_id 小队，随正常回合原子提交、随快照恢复。
旧档初次使用按完全相同的非空位置初始化，未知位置单独处理；不会把已在不同地点的人拉回来。
初始化后不再按位置自动合并，显式分头即使还在同一地点也保持独立。新加入成员默认单独，需会合。
普通移动由引擎补齐当前小队所有人的 location_ops；participants 漏写不拆队，个人发言不强制队友参与。
`travel_change` 的 split/join 需要合法成员和具体依据，并经合并的行动/对白检查确认；复核不可用不放行变化。
join 要求当前已在同一个确切地点；先抵达，再确认会合。危险决定和共同资源仍走原有表决，不因同行跳过同意。
小队记录与权威位置不符时按位置拆开（只拆不并），不做传送、也不会把已分开的人拉回来。
不拆的话，任何绕过同行结算的移动（例如主持推进单独挪走一名成员）都会留下一支与事实不符的小队，
之后该成员每次普通移动都撞上「同行记录与实际位置冲突」且无从修复。主持推进同样收敛 travel_groups。
测试见 test_travel_groups.py。

### 行动兑现与章节衔接

成稿检查同时读取精简的本轮行动契约：原始行动、个人现场、上一轮已结算结果、队伍和权威骰果。
即使未启用 NPC 独立决策，存在行动契约的 resolve 结果也检查是否遗漏核心互动或无依据跳场；
与对白检查合并一次调用，仍最多检查初稿及修复稿各一次。检查不可用的降级策略不变。
章节进度不授权转场，原作不等于本局已发生；已完成的交涉不应重新成为必做选项。
repair_prompt 只重发这些结构化行动字段，不重发完整历史。错误草稿不是既成事实，
行动遗漏/虚构转场的修复应同步纠正对应状态操作，但不得改变已提交事实及权威骰果。
测试 test_action_contract.py 与 test_engine.py 覆盖跳过会面的初稿被拒绝、修复后只提交一轮。

运行 `test_npc_direction.py`、`test_npc_death_persistence.py`、`test_personal_continuity.py` 和 `test_engine.py`。
`tools/install_royal_npc_direction.py` 默认只校验；`--apply` 有最新回合/版本保护、SQLite 备份和审计。
该脚本只校正人物设定和参考配置，不修改历史事件、已完成里程碑、人物位置、生死或玩家状态。
新增 Python 代码需要重新加载插件或重启相应进程；仅更新数据库不会让旧进程自动拥有新实现。
